## Purpose
This PR is created for two purposes:
1. Add trtllm fp4 kernel to be used in compressedtensorw4a4 method
2. Create a mutually used function for modelopt and compressedtensorw4a4 path to call flashinfer trtllm moe fp4 kernel



## Test Plan
### Accuracy test
Tested all code paths before and after the code change, including:
1. modelopt + trtllm fp4 moe
2. modelopt + flashinfer cutlass moe
3. compressedtensor + cutlass moe
4. compressedtensor + flashinfer cutlass moe
5. compressedtensor + flashinfer trtllm fp4 moe
The eval task is gsm8k and results are listed below 

The eval is based on nvfp4 ckpoint generated by llm-compressor for Qwen3-VL-235B-A22B for compressed tensors path and nvidia/Qwen3-235B-A22B-FP4 on modelopt path. The serving command is 

`vllm serve model_name    --tensor-parallel-size 2   --mm-encoder-tp-mode data --enable-expert-parallel --async-scheduling&
`
and eval command is 
`lm_eval --model local-completions --tasks gsm8k --model_args model=model_name,base_url=http://0.0.0.0:8000/v1/completions,max_retries=3,tokenized_requests=False,timeout=1200,max_gen_toks=2048,max_length=8192 --batch_size 2048 --trust_remote_code --limit 0.5`

> **![P1 Badge](https://camo.githubusercontent.com/c595229c0ecb6ee85b9c7804144d495f131a495ec87091fea2b262d954c9a92d/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f50312d6f72616e67653f7374796c653d666c6174) FlashInfer TRT path uses inverted activation scales**
> When the W4A4 compressed-tensor path routes to the new FlashInfer TensorRT backend, the activation scales passed to `flashinfer_trtllm_fp4_moe` are still computed with the old per-expert/inverted convention (`g1_alphas` uses `1 / w13_input_global_scale`). The shared kernel expects the same scale layout as the ModelOpt path (see `modelopt.py` lines 1496–1507), which multiplies by the global scale and passes its reciprocal to the kernel. With the current computation the input activation quantization and output scaling are off by a reciprocal, so the TRT-LLM MoE kernel will produce incorrect results whenever this backend is enabled for compressed tensors.
> 
> ℹ️ About Codex in GitHub

The scale saved in these two different checkpoints are the inverse of each other so this difference will result in the correct g1_alphas value the kernel expects.
