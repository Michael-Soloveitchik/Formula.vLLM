## Gap between the author's absolute numbers and ours

- verdict: **hardware (CPU share hidden) + config** — Author: `--num-prompts 30000`, 268→274 req/s (+2.07 %, single run, no sd) on an 8-GPU node; ours `--num-prompts 2000`, 30.1→30.2 req/s (+0.2 %, sd 0.7 %). The PR saves ~400 µs of host work per step; it is only visible when the step is host-bound. On the 5070 Ti the same opt-125m step is ~9× slower on the GPU side (26 K vs 235 K tok/s), so the host saving is <0.3 % of step time — consistent with what we measured. Secondary config gap: vLLM 0.10.1 (`vllm/engine/arg_utils.py:1633`) defaults `max_num_seqs=1024, max_num_batched_tokens=16384` when the GPU has ≥ 70 GiB (and is not an A100), else `256 / 8192`, so the author's slot-mapping loop ran over 4× more requests and 2× more tokens per step. To match the author's args: add `--max-num-seqs 1024 --max-num-batched-tokens 16384` and `--num-prompts 30000` (≈16 min/run; 1 repeat per arm is enough, the metric is already an average over 30000 requests). Even then expect ≤1 % here. Verdict: hardware; the author's 2 % is below any reasonable noise gate anyway.

## Measurement policy (as pipeline/run_one.sh implements it)

- repeats: 1 per arm; ABBA across arms per repeat (A,B,B,A,A,B,...); one run = one `docker run` of the workload cmd per arm per repeat (same image, arm tree swapped in by the prelude)
- GPU pin `--gpus device=0`, env ['CUDA_DEVICE_ORDER=PCI_BUS_ID', 'CUDA_VISIBLE_DEVICES=0', 'HF_HUB_DISABLE_PROGRESS_BARS=1'], `--shm-size=2g`, per-run cap `WL_TIMEOUT=20m`
- GPU warm-up 2.0 s in the prelude; contention gate: wait while another tenant uses the GPU (>5 % util or a foreign compute process >1 GiB) or the CPU (load1 > nproc/2) (max wait 600 s, then run anyway, flagged in data/pr_<n>/work/contended_<arm>_<i>.txt)
- arm isolation `files`: overlay ONLY task.json:source_files from the arm over the wheel's own tree; machine.py snapshot per workload run -> data/pr_<n>/work/machine_<arm>_<i>.json
- noise model: measure.py: paired log-speedup, MAD sigma, theta = clip(k*sigma, theta_min, theta_max) with k/theta from config.yaml:measure
